In Replit, code is hosted directly in the cloud inside an isolated, browser-based container environment. [1, 2]
How Hosting Works on Replit

Cloud-Based Workspace: Every project (called a "Repl") runs on a cloud virtual machine with its own file system, terminal, and automatic package management. You do not need to configure a local server or environment on your own computer. [1, 2, 3, 4]
Instant Preview and URLs: When you run a web server or application inside Replit, it automatically exposes your app via a unique subdomain (like your-repl-name.username.repl.co), letting you view and share your live code instantly. [1, 2]
Built-in Deployments: Replit offers a Deployments feature that lets you publish your project to production with one click, offering persistent uptime, custom domains, and dedicated resources via Reserved VMs. [1, 2]
Alternative Exporting: If you prefer not to host production apps directly on Replit, you can push your code via version control to GitHub and host it on external platforms like Netlify, Vercel, or AWS. [1, 2, 3]
For a deeper dive into the platform's cloud capabilities, check out Replit or read about their approach from localhost to live. [1]

How to share an instant preview and URL and will it be public by default?
Yes, by default, both your instant preview URL and your published app are public to the web. Anyone who gets a hold of the generated link can view your live app. [1, 2]
Replit handles URLs in two distinct stages: Development Previews and Published Deployments. [1]


Instant Preview (Development URL)
When you click Run on a web application, Replit immediately generates a temporary preview window and a development URL formatted as UUID.servername.replit.dev. [1]


How to share it: Click the text ending in .replit.dev inside the workspace's built-in browser location bar to copy it, or open it in a new tab and copy the address. [1]
Is it public? Yes, by default. Anyone with the link can view it, making it perfect for quick feedback from a peer. [1]
The Catch: It is temporary. It only stays live while you are actively working inside the Replit editor and changes frequently when you reopen the app. [1]
How to make it private: If you want to lock it down during development, go to Developer Tools → Networking tab → toggle on Private development URL. This restricts access so only you and authorized workspace collaborators can see it. [1]


Live Production (Published URL)
For permanent sharing, you must officially deploy your work. [1, 2]


How to share it: Click the rocket icon or Publish button in the top-right corner of your workspace. Replit will package your app and issue a permanent, stable link under the your-app-name.replit.app domain.
Is it public? Yes, apps published from personal workspaces default to Public.
How to change visibility: Before hitting final confirmation in the publishing dialog, navigate to the "Who can access your app" configuration panel. You can change it from Public to Password protected, Workspace only, or Invite only. (Note: resticting access to workspace/invite-only requires a paid tier like the Core or Pro plan). [1, 2, 3, 4]
For step-by-step visual guidance, check out the official Replit Docs on Development URLs and their guide on how to Publish Your App.

When you visit another team's Replit development URL (the temporary UUID.servername.replit.dev link), what you see depends entirely on whether you are just looking at the rendered web app or if you have been invited into the workspace code editor. [1, 2]


If you only have the .replit.dev URL (Web Visitor)
If a team simply sends you their active development link, you act as an external user testing the application. [1]


What you CAN see: The front-end user interface exactly as it looks in a browser. You can click buttons, fill out forms, and test the app's current functionality in real-time. [1]
What you CANNOT see: You cannot see the source code, the file directory, the terminal, or the server logs. It looks like a normal website. [1]
Important Caveat: You will only see the app if the team is actively running the code in their workspace. If they stop the project or close their browser tabs, the URL will break and display an error page. [1, 2]


If you click "View Code" or look at the Workspace URL
If they share the main project workspace link (://replit.com) or you navigate to their public profile:


For a Public Repl: You can see all the source code, files, and configurations. You can also "Fork" (copy) the project into your own account. However, you cannot see their private environment variables (like API keys or database passwords saved in the Replit Secrets panel). [1]
For a Private / Team Repl: If you are not an authorized member of their team workspace, trying to view the workspace will result in a "404 Not Found" or access-denied page. [1, 2]
